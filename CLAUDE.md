# Work rules

- Do not change code without the user's clear permission. If you find a problem (bug, leak, etc.) — report it and suggest a fix, but do not apply it yourself until the user says yes.
- When reviewing/checking code, do not give an explicit diagnosis (exact line/bug/why) or write example fix code — give only a vague hint (what area/variable to compare) so the user works it out themselves. Give the explicit answer or a fix only if the user explicitly asks for it and confirms.
